# 11 · Subagents 子代理

> 本节目标：理解什么是子代理（subagent），它如何帮你"派分身并行干活"和"隔离上下文"。进阶功能，了解概念为主。

## 是什么

**Subagent（子代理）** 是 Claude Code 派出去的"分身"。主对话（你正在交互的这个）可以委派一个独立的子代理去完成某个子任务，子代理有**自己独立的上下文窗口**，干完把**结论**带回来。

类比：你是项目经理，遇到一个需要大量调研的子任务，与其自己埋头翻一堆文件，不如**派一个助理去查，让他只把结论汇报给你**。你的"办公桌"（主上下文）保持干净。

## 为什么有用

1. **隔离上下文，保持主线干净** 🧹
   比如"在整个代码库里搜索所有用到旧 API 的地方"——这会读一大堆文件。让子代理去读，它只把"找到这 8 处"带回来，你的主对话不会被一堆文件内容塞满。

2. **并行加速** ⚡
   多个互相独立的子任务可以**同时**派多个子代理去做，比一个个串行快得多。例如同时让 3 个分身分别审查 3 个模块。

3. **专门化** 🎯
   可以有专门角色的子代理，比如"代码审查专家""探索搜索专家"，各司其职。

## 怎么用

大多数时候，**Claude Code 会在合适的时候自动派子代理**，你不用操心。你也可以显式要求：

```
用一个子代理在整个项目里找出所有 TODO 注释，只汇总结果给我
```

```
并行审查 sample-app 里的每个 Python 文件，分别给出改进建议
```

### 管理子代理：`/agents`
输入 `/agents` 可以查看和配置子代理（包括自定义专门的子代理角色）。

### 常见内置子代理类型
不同版本可能不同，常见的有：
- **通用型（general-purpose）**：处理复杂多步任务、宽泛搜索
- **探索型（Explore）**：只读地大范围搜代码、定位文件
- **规划型（Plan）**：设计实现方案

## 子代理 vs 主对话

| | 主对话 | 子代理 |
|---|--------|--------|
| 上下文 | 你的主线，持续累积 | 独立、用完即弃 |
| 你能看到过程吗 | 能，直接交互 | 主要看它的最终汇报 |
| 适合 | 决策、把关、连续任务 | 一次性的调研/搜索/独立子任务 |

> 💡 关键认知：子代理的"过程"不会塞进你的主上下文，只有"结论"会回来。这正是它帮你省上下文的原理。

## 什么时候关注它

- 入门期：知道"它有时会自己派分身去搜东西"就够了，不用主动用。
- 进阶期：当你要在大型代码库里做宽泛搜索、或有多个独立子任务想并行时，主动让它用子代理。

## 动手试一试

本项目较小，但仍可体会：

```
派一个子代理去读完整个 docs/ 目录，然后只用 5 句话总结这套教程在教什么
```

观察它如何"委派 → 子代理读一堆文件 → 只把精炼总结带回来"，而你的对话没有被 14 篇文档的全文淹没。
