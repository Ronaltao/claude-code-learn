# 07 · 计划模式

> 本节目标：学会用"计划模式"让 Claude Code 先想后做，避免它在大改动上一头扎错方向。

## 是什么

**计划模式（Plan Mode）** 是一种**只读**工作模式：在这个模式下，Claude Code **不会修改任何文件、不会运行有副作用的命令**，它只会：

1. 读代码、做调研，
2. 给你一份**详细的实施方案**，
3. 等你**批准**后，才退出计划模式去真正动手。

类比：盖房子之前先看图纸。你确认图纸没问题，工人才开始砌墙 —— 而不是砌错了再砸掉重来。

## 为什么需要它
新手最容易踩的坑：丢一个大需求，它噼里啪啦改了一堆文件，结果**方向就错了**，白干还得清理。

计划模式把"昂贵的执行"前面加了一道"便宜的对齐"：

- ✅ 改动越大、越复杂，越该先用它
- ✅ 你能在它动手前发现"它理解错了需求"
- ✅ 你能把它的方案改一改，再让它执行

## 怎么用

### 进入计划模式
按 **`Shift + Tab`** 循环切换权限模式，切到 **plan mode**（输入框附近会显示）。然后正常提需求：

```
我想给 calculator.py 增加历史记录功能：每次计算后保存到一个列表，并能打印历史。给我实施方案。
```

它会**只读分析**，然后输出一份方案，通常包括：
- 要改哪些文件、各自改什么
- 新增什么函数/类
- 可能的风险或需要你决定的点

### 审查方案
认真读这份方案。如果：
- **满意** → 批准，它退出计划模式开始执行。
- **要调整** → 直接说"方案不错，但历史记录请存到文件而不是内存"，它会改方案。
- **方向全错** → 说清楚你真正想要的，让它重做方案。

### 执行
批准后它就按方案动手，这时回到正常的"改文件要批准"流程（见 [第 06 节](06-permissions.md)）。

## 什么时候用 / 不用

| 适合用计划模式 | 不必用 |
|----------------|--------|
| 新功能开发 | 改一个错别字 |
| 跨多文件的重构 | 单行修复 |
| 不确定它是否理解需求 | 你已经说得非常具体的小改动 |
| 高风险改动（动核心逻辑） | 纯读代码、问问题 |

## 一个高效组合拳

很多老手的默认工作流：

```
1. Shift+Tab 切到计划模式
2. 描述需求 → 拿到方案
3. 审方案、提修改意见 → 方案定稿
4. 批准执行 → 切回普通/自动接受模式让它干
5. 干完让它跑测试验证
```

把"想"和"做"分开，是用好 AI 编程最重要的习惯之一。

## 动手试一试

在本项目里：

1. `Shift + Tab` 切到计划模式。
2. 输入：
   ```
   我想给 exercises/sample-app/calculator.py 增加一个"求幂"的方法。先给我实施方案，不要改代码。
   ```
3. 观察它**只给方案、没动文件**。
4. 回它一句"方案可以，但请把方法命名为 power 而不是 pow"，看它如何调整。
5. （可选）批准并让它执行，然后用 Git/diff 看改动 —— 注意这是练习项目，改了也没关系。
