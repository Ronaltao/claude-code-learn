# 13 · Hooks 钩子

> 本节目标：理解 Hooks 如何实现"自动化"——比如"每次它改完代码就自动跑一次格式化/测试"。进阶功能，了解概念为主。

## 是什么

**Hook（钩子）** 是你预先设定的"自动触发的动作"：当 Claude Code 发生某个**事件**时（比如改完一个文件、提交前、会话结束时），系统会**自动执行**你指定的命令 —— 不需要你开口，也不需要 AI 主动想到。

关键区别：
- 让 AI"每次改完帮我跑下格式化"——它**可能忘**，因为这要靠它每次都记得。
- 用 Hook 绑定"文件被编辑后 → 运行格式化"——**由 Claude Code 这个程序保证执行**，绝不遗漏。

类比：Hook 就像"如果……就自动……"的规则。家里的"开门就亮灯"——你不用每次手动开灯，传感器自动触发。

## 为什么用它

凡是"**每次 X 之后都应该做 Y**"的事，都适合 Hook：

- ✏️ 每次编辑 `.py` 文件后 → 自动运行 `ruff format`
- ✅ 每次改完代码 → 自动跑相关测试
- 🔒 提交前 → 自动检查有没有把密钥写进代码
- 🔔 任务完成时 → 发个桌面通知 / 响一声
- 📝 每次运行某命令前 → 记录日志

## 怎么用

Hooks 配置在 `settings.json` 里（见 [第 14 节](14-settings.md)）。你为某个**事件**绑定一条**要执行的命令**。

常见的事件时机（hook 类型）大致有：
- **工具使用前 / 后**（比如文件编辑前后、命令执行前后）
- **会话开始 / 结束**
- **Claude 停止响应时**

### 示意配置

一个"每次编辑文件后自动用 prettier 格式化"的钩子大概长这样（示意，以官方文档为准）：

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "npx prettier --write ." }
        ]
      }
    ]
  }
}
```

含义：在 `Edit` 或 `Write` 工具用完之后，自动执行 prettier 格式化。

> 配置 Hook 有一定门槛，且不同版本字段可能有差异。**最省事的办法**：直接让 Claude Code 帮你配 ——"帮我加一个 hook：每次编辑 Python 文件后自动运行 ruff format"。它知道当前版本的正确写法（也有专门的配置技能可用）。

## 重要：Hook 是"程序行为"，不是"记忆"

新手常误以为"我在 CLAUDE.md 里写一句'每次改完跑测试'就行了"。但那只是**提示**，AI 仍可能漏做。**真正的强制自动化必须用 Hook**，因为 Hook 由 Claude Code 这个程序执行，而不是靠 AI 自觉。

> 记住这条判断：要"每次/自动/之前之后必须做某事" → 用 Hook，而不是写进记忆。

## 安全须知

- ⚠️ Hook 会**自动执行命令**，配错可能有破坏性。配置时想清楚命令的副作用。
- ✅ 从简单、安全的命令开始（格式化、lint），熟悉后再加复杂的。

## 什么时候关注它

- 入门期：**可以先跳过**。知道"想要自动化就找 Hook"即可。
- 进阶期：当你发现某件事"每次都得做、还老忘"时，就该上 Hook 了。

## 动手试一试

不用真的配，先建立认知：

1. 问 Claude Code：
   ```
   解释一下 Claude Code 的 hooks 能在哪些时机触发，各举一个实用例子
   ```
2. 想一个你自己的场景："我希望每次 ____ 之后，自动 ____"。
3. （可选，进阶）让它帮你真的配一个简单 hook，比如编辑文件后打印一行日志，体验自动触发。
