# 06 · 权限与安全

> 本节目标：搞懂"它会不会乱改/乱删我的东西"，学会用三种权限模式掌控全局。这是放心使用的前提。

## 是什么

Claude Code 内置了一套**权限系统**：默认情况下，**所有有风险的操作都会先征求你同意**，你点头它才做。

哪些算"有风险"？

- 修改文件（Edit / Write）
- 删除文件
- 运行命令（Bash），尤其是 `rm`、`git push` 这类
- 访问网络

而**只读操作**（读文件、搜索代码）通常不打扰你。

> 🔑 一句话安心：**默认配置下，它不会在你不知情的情况下改动任何东西。**

## 三种权限模式

用 **`Shift + Tab`** 在三种模式间**循环切换**，当前模式会显示在输入框附近。

### 1. 普通模式（默认）🛡️
每个危险操作都停下来问你 `y/n`。最安全，新手默认就用这个。

### 2. 自动接受模式（auto-accept edits）⚡
自动批准**文件编辑**，不再每次问你。适合：
- 你已经信任这个任务
- 大量重复的小改动，一个个批准太累

⚠️ 代价：你失去了逐个把关的机会，**务必事后用 Git diff 整体 review**。

### 3. 计划模式（plan mode）📋
**只读**！它只能看、不能改，先给你一份**实施方案**，你确认后才进入执行。适合大改动前对齐思路 —— 这么重要，[第 07 节](07-plan-mode.md)单独讲。

| 模式 | 改文件 | 跑命令 | 适用 |
|------|:------:|:------:|------|
| 普通 | 问你 | 问你 | 默认、最稳 |
| 自动接受 | 自动 | 问你 | 信任的任务、提速 |
| 计划 | ❌只读 | ❌只读 | 动手前先出方案 |

## 怎么用：批准一个操作

当它要做危险操作，你会看到提示，通常有几个选项：

- **同意一次**（yes）
- **同意，且以后同类操作不再问**（yes, and don't ask again for ...）—— 谨慎用
- **拒绝**（no）—— 它会停下并问你接下来怎么办

**新手建议**：先逐个看清楚再批准；等熟悉了某类安全操作（比如运行测试），再选"以后不再问"。

## `/permissions`：管理规则

输入 `/permissions` 可以查看和编辑权限规则，比如：

- **允许（allow）**某类命令永远不问，例如允许所有 `npm test`
- **拒绝（deny）**某类操作永远禁止，例如永远禁止 `rm -rf`
- **询问（ask）**保持每次确认

这些规则可以持久保存到配置文件里（详见 [第 14 节 settings.json](14-settings.md)），下次启动依然生效。

## 安全最佳实践（重要）

1. **正式项目务必在 Git 仓库里用**：动手前 `git status` 保持干净，出问题 `git checkout .` 一键还原。
2. **看清再批准**，尤其是 `Write`（整体覆盖）和任何 `rm`、`git push`、`> 文件` 这类。
3. **不确定就拒绝**：拒绝后告诉它"先别动，解释给我听"。
4. **谨慎对待"不再询问"**：只对真正安全、重复的操作开。
5. **敏感目录设 deny**：用 `/permissions` 把 `.env`、密钥、生产配置等加入禁止名单。

## 动手试一试

1. 启动后按几次 `Shift + Tab`，观察输入框附近的模式标识在"普通 → 自动接受 → 计划"间切换。
2. 切回**普通模式**，让它做一个写文件的操作（比如"新建一个 test.txt"），体验批准提示，然后**选拒绝**，看它如何反应。
3. 输入 `/permissions` 看看当前规则长什么样。
