# 08 · CLAUDE.md 项目记忆

> 本节目标：学会用 `CLAUDE.md` 让 Claude Code 记住你项目的规范和背景，从此少解释、少返工。

## 是什么

**`CLAUDE.md`** 是放在项目里的一个 Markdown 文件。Claude Code **每次启动都会自动读它**，把里面的内容当作"长期记忆"和"工作须知"。

没有它：每次新会话你都得重新解释"我们用 pytest 不用 unittest"、"代码注释写中文"……
有了它：这些一次写好，它永远记得。

> 💡 本学习项目的根目录就有一个真实的 [CLAUDE.md](../CLAUDE.md)，现在就可以打开看看示范。

## 放在哪里
| 位置 | 作用范围 | 用途 |
|------|----------|------|
| 项目根目录 `./CLAUDE.md` | 这个项目 | 项目规范（最常用，建议提交进 Git 给团队共享） |
| 子目录 `./某模块/CLAUDE.md` | 该子目录 | 模块特定的说明 |
| 个人全局 `~/.claude/CLAUDE.md` | 你的所有项目 | 你的个人偏好 |
## 该写什么（关键）
写**它猜不到、但每次都需要知道**的东西。好的 CLAUDE.md 通常包含：
- **项目是什么**：一句话说明用途和技术栈
- **怎么运行/测试/构建**：`npm run dev` / `pytest` 等命令
- **代码规范**：命名风格、注释语言、格式化工具
- **架构要点**：入口在哪、核心模块怎么分
- **禁忌**：哪些文件/目录不要动，哪些坑要避开

### 一个好例子

```markdown
# CLAUDE.md

## 项目简介
一个 FastAPI 后端，提供订单管理 API。

## 常用命令
- 启动开发服务器：`uvicorn app.main:app --reload`
- 跑测试：`pytest`
- 代码格式化：`ruff format .`

## 约定
- 所有代码注释、commit message 用中文
- 新接口必须配套写测试，放在 tests/ 下
- 数据库模型改动后要生成 migration

## 注意
- 不要修改 app/legacy/ 目录（历史代码，正在废弃）
- .env 是密钥，永远不要读取或打印其内容
```

### 写作要点

- ✅ **简洁**：它会占用上下文，别写成长篇文档，挑重点。
- ✅ **具体**：写"用 4 空格缩进"，而不是"代码要规范"。
- ✅ **持续更新**：发现它老犯同一个错，就把规则补进去。

## 怎么创建

### 方法一：`/init`（推荐新项目用）
在项目里运行斜杠命令：
```
/init
```
它会自动分析你的代码库，生成一份初稿 `CLAUDE.md`。然后你再手动精修。

### 方法二：手写 / `/memory`
直接新建文件，或用 `/memory` 命令在编辑器里打开它编辑。

### 方法三：用 `#` 随手追加 ⭐很方便
对话中以 `#` 开头输入一句话，会被快速追加进记忆。比如它刚用错了测试框架，你打：
```
#本项目统一用 pytest，不要用 unittest
```
下次它就记得了。

## 它和"对话上下文"的区别

- **CLAUDE.md**：持久的、跨会话的记忆，`/clear` 也不会丢。适合"永远成立"的规则。
- **对话上下文**：当前这次会话的临时记忆，`/clear` 后清空。适合"这次任务"的细节。

## 动手试一试

1. 打开本项目的 [CLAUDE.md](../CLAUDE.md) 读一遍，体会"项目记忆"长什么样。
2. 启动 `claude`，问它：
   ```
   根据项目记忆，这个项目有什么特别的约定我需要注意？
   ```
   看它能不能复述出 CLAUDE.md 里的约定 —— 证明它确实"记住"了。
3. 用 `#` 追加一条你自己的规则，再问它一遍，看是否生效。
