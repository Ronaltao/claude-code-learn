# 09 · Git 与版本控制

> 本节目标：让 Claude Code 帮你处理日常 Git 工作 —— 写 commit、看改动、开分支、提 PR，并理解为什么"配合 Git 使用"能让你用得更放心。

## 是什么

Claude Code 对 **Git** 有很好的支持。它能：

- 查看改动状态和 diff
- **替你写高质量的 commit message**（这点超省心）
- 创建分支、切换分支
- 提交、推送
- 用 `gh` 命令创建 Pull Request
- 帮你审查改动（`/review`）

## 为什么 Git + Claude Code 是绝配

这是**安全使用的基石**：

- 改之前 `git status` 干净 → 改之后能清楚看到它动了什么。
- 改坏了？`git checkout .` 一键还原，毫无心理负担。
- 所以：**正式项目永远在 Git 仓库里用 Claude Code**，让你敢于放手让它干。

## 怎么用

### 看改动
```
看一下当前有哪些改动还没提交
```
它会跑 `git status` / `git diff` 并给你总结。

### 提交（最常用）⭐
做完一波改动后：
```
把刚才的改动提交，commit message 用中文清楚描述做了什么
```
它会：查看改动 → 理解你做了啥 → **自动写好 commit message** → 提交（提交前通常会让你确认）。

> 比起自己憋半天 commit message，让它根据实际 diff 来写，又快又准。

### 开分支干活
```
帮我新建一个分支 feature/add-history，然后在上面实现历史记录功能
```

### 提 PR（需要装 gh CLI）
```
把当前分支推上去，并创建一个 PR，标题和描述用中文写清楚
```

### 审查改动
```
/review
```
让它审查当前的代码改动，挑出潜在 bug 和可改进处。也可以直接说"review 一下我刚才的改动"。

## 安全须知

- ⚠️ **`git push` 是对外操作**：它默认会先问你。推之前确认推的是对的分支。
- ⚠️ **不要让它随意 `git reset --hard` 或强推**：这类破坏性操作要格外小心，看清楚再批准。
- ✅ **提交粒度**：建议一个逻辑改动一次提交，方便回溯。可以让它"分成几个有意义的小提交"。
- ✅ **本学习项目默认不是 Git 仓库**：你可以 `git init` 一下来练习 Git 相关操作。

## 实用工作流示例

一个典型的"用 Claude Code 完成一个小功能"的完整流程：

```
1. （计划模式）描述需求，拿到方案并确认
2. 切回普通模式，让它实现
3. "跑测试确认通过"
4. "review 一下这次改动有没有问题"
5. "新建分支 feature/xxx，把改动提交，message 用中文"
6. "推上去并开个 PR"
```

从需求到 PR，全程自然语言。

## 动手试一试

在本项目目录（先 `git init` 把它变成 Git 仓库）：

```bash
cd f:/claude_code_project/project1
git init
```

然后启动 `claude`：

1. 让它新建一个文件并写点内容（比如 `echo` 一个 hello.txt）。
2. 输入：
   ```
   看一下现在的 git 状态，然后把改动提交，commit message 用中文
   ```
3. 观察它怎么查状态、怎么自动拟 message、提交前怎么让你确认。
