# 04 · 让它读写文件

> 本节目标：掌握 Claude Code 最核心的能力 —— 读代码、改代码、新建文件，并理解它是怎么安全地操作你文件的。

## 是什么

这是 Claude Code 和普通聊天 AI 最大的不同：**它能直接读写你磁盘上的文件**。背后是几个"工具"：

| 工具 | 作用 | 会不会问你 |
|------|------|-----------|
| `Read` | 读取文件内容 | 读取通常不问（只读、安全） |
| `Edit` | 修改文件的某一部分 | **会问**（默认） |
| `Write` | 新建或整体覆盖文件 | **会问**（默认） |
| `Glob` / `Grep` | 按文件名/内容搜索 | 不问（只读） |

> 🔑 核心原则：**读取免打扰，修改要批准**。所以你不用担心它偷偷改坏东西。

## 怎么用

### 读文件 / 读懂项目

直接说就行，它会自己决定读哪些：

```
解释一下 exercises/sample-app/calculator.py 这个文件
```

```
这个项目的入口在哪？带我过一遍整体结构
```

它可能会连续读好几个文件来建立全局理解 —— 这是正常的。

### 改文件

描述你要的改动，它会展示一个 **diff（改动对比）** 让你确认：

```
calculator.py 里的 divide 函数没有处理除以 0 的情况，帮我加上：除数为 0 时抛出 ValueError，提示"除数不能为零"
```

它会停下来给你看"哪几行删、哪几行加"，**你看清楚再批准**。这是你最重要的把关时刻。

### 看懂 diff（改动对比）

批准前你会看到类似：

```diff
  def divide(a, b):
-     return a / b
+     if b == 0:
+         raise ValueError("除数不能为零")
+     return a / b
```

- `-` 红色：要删掉的行
- `+` 绿色：要新增的行
- 没符号：保持不变的上下文

**养成习惯：每次都瞄一眼 diff，确认它没改到不该改的地方。**

### 新建文件

```
在 sample-app 目录下新建一个 README.md，简单说明这个小程序的功能和怎么运行
```

### 批量/跨文件修改

它擅长成片的重复改动：

```
把整个项目里所有 print 调用都改成用 logging 模块输出
```

它会逐个文件给你确认。

## 安全须知（新手必读）

- ✅ **改动前一定看 diff**，尤其是"覆盖整个文件"的 `Write` 操作。
- ✅ **重要项目用 Git**：改之前 `git status` 干净，万一改坏 `git checkout .` 就能还原。本学习项目无所谓，正式项目务必这么做。
- ⚠️ **它可能改得不对**：批准 ≠ 正确。改完记得跑测试、自己 review。
- ✅ **不想让它动某些文件**？直接告诉它："不要修改 config/ 目录下的任何文件"。

## 进阶：让它"读—改—验证"闭环

最高效的用法是让它自己形成闭环：

```
test_calculator.py 里 test_divide 这个测试失败了。
帮我：1) 找出原因 2) 修复 calculator.py 3) 重新跑测试确认通过
```

它会读测试 → 读源码 → 改代码 → 跑测试 → 看结果 → 必要时再改，直到通过。这就是 Claude Code 真正的威力。

## 动手试一试

在本项目里试这一连串（这正是下一阶段练习的预热）：

```
1. 读一下 exercises/sample-app/calculator.py，列出所有函数
2. 在 sample-app 目录新建一个 NOTES.md，把你刚才的总结写进去
```

注意观察：第 1 步它读文件**没问你**，第 2 步要写文件**停下来等你批准**。这就是"读取免打扰、修改要批准"。
