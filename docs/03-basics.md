# 03 · 基础交互

> 本节目标：学会怎么提问、怎么打断、怎么引用文件、怎么看它在干什么。这是每天都要用的基本功。

## 是什么

和 Claude Code 打交道，核心就是一个**对话循环**：你说需求 → 它干活（可能问你要不要批准某个操作）→ 给结果 → 你接着说。下面是让这个循环顺畅的几个关键技能。

## 怎么用

### 1. 怎么提问：越具体越好

它不会读心。对比一下：

| 😐 模糊 | 😀 清楚 |
|--------|--------|
| "优化一下代码" | "calculator.py 里的 divide 函数没处理除零，帮我加上异常处理" |
| "这里有 bug" | "运行 test_calculator.py 时 test_divide 失败，帮我定位原因" |
| "加个功能" | "给 Calculator 类加一个求平方根的方法，并补上对应测试" |

**技巧**：说清楚 **在哪个文件、什么现象、想要什么结果**。

### 2. 用 `@` 精准引用文件

在输入框打 `@`，会弹出文件名补全。比起描述"那个计算的文件"，直接引用更准：

```
解释一下 @exercises/sample-app/calculator.py 的整体结构
```

### 3. 打断它：`Esc`

它正在做的事不对劲？**按 `Esc` 立刻打断**，然后纠正方向：

```
（Esc）停，不要改那个文件，我只想让你先解释，不要动代码
```

> 这是新手最该先学会的"刹车键"。不怕它跑偏，随时能停。

### 4. 回退/编辑历史：`Esc` `Esc`

连按两次 `Esc`，可以回到之前某条消息重新编辑 —— 相当于"时光倒流"，重走一遍。

### 5. 看懂它在干什么

它干活时，你会在屏幕上看到它**正在调用的工具**，比如：

- `Read` —— 它在读某个文件
- `Edit` / `Write` —— 它要改/写文件（通常会停下来等你批准）
- `Bash` —— 它要运行一条命令（同样会问你）
- `Grep` / `Glob` —— 它在搜索代码

看到要批准的操作，认真看一眼它**要改什么/跑什么**，再决定 `y`（同意）还是拒绝。批准机制详见 [第 06 节](06-permissions.md)。

### 6. 多轮推进，别想一步到位

复杂任务拆成几轮更可控：

```
第1轮：先读懂 sample-app，告诉我有几个函数、各自做什么
第2轮：good，现在找出其中可能有 bug 的地方，先别改
第3轮：修复你说的第一个 bug，并跑测试确认
```

### 7. 进入 bash 模式：`!`

输入框里以 `!` 开头，可以**直接敲 shell 命令**（不经过 AI），比如 `!ls`、`!git status`。适合快速看一眼状态。

## 几个好习惯

- ✅ **任务切换前 `/clear`**：开始一个全新任务前清空上下文，更快更准更省钱。
- ✅ **让它自证**：改完加一句"跑测试确认通过"，别全信它说"改好了"。
- ✅ **不懂就问**：直接问"这个项目用什么包管理工具？"，它会自己查。
- ✅ **给反馈**：它做得好/不好都告诉它，"很好，照这个风格继续"或"不对，应该用 X 而不是 Y"。

## 动手试一试

在本项目目录启动 `claude`，依次体验：

1. 用 `@` 引用文件提问：
   ```
   用一句话总结 @exercises/sample-app/calculator.py 是做什么的
   ```
2. 故意让它开始一个动作，然后**按 `Esc` 打断**，感受"刹车"。
3. 用 `!` 跑一个命令：`!python --version`
4. 做完后 `/clear` 清空，准备下一个任务。
